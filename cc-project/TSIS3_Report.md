# TSIS 3: CFO Bot & Agentic Architecture Project Report

## Phase 1: System Specification (SSOT)

**Project:** CFO Bot (Cloud Cost Calculator for AI Applications)  
**Version:** 1.0 | **Status:** Approved for Implementation

---

### 1. Executive Summary

The CFO Bot is a client-side, real-time web application designed to calculate the estimated monthly cloud infrastructure and API costs for operating an AI-powered Chatbot. This document serves as the **Single Source of Truth (SSOT)**.

---

### 2. Cloud Components & Architecture Scope

| Component | Service | Description |
|-----------|---------|-------------|
| **Compute** | Google Cloud Functions (Gen 2) | Serverless Logic |
| **Database** | Google Cloud Firestore (Native Mode NoSQL) | State & History |
| **LLM API** | External Third-Party Model (e.g., OpenAI GPT-4o-mini) | AI Inference |
| **Bandwidth** | Google Cloud Internet Egress | Data Transfer |

---

### 3. Input Variables

- **U** = Monthly Active Users (MAU). Integer, `U ≥ 0`.
- **M** = Average Messages per User per Month. Integer, `M ≥ 0`.
- **Derived:** `T_msg` = Total Monthly Messages = `U × M`

---

### 4. Mathematical Cost Models & Pricing Logic

#### Compute Cost (`C_comp`)
> Rate: $0.40 per 1M invocations

```
C_comp = (T_msg / 1,000,000) × 0.40
```

#### Database Cost (`C_db`)
> 2 Reads ($0.06/100k), 1 Write ($0.18/100k) per message

```
C_db = ((T_msg × 2) / 100,000) × 0.06 + (T_msg / 100,000) × 0.18
```

#### LLM API Cost (`C_llm`)
> 500 Input tokens ($0.15/1M), 200 Output tokens ($0.60/1M) per message

```
C_llm = ((T_msg × 500) / 1,000,000) × 0.15 + ((T_msg × 200) / 1,000,000) × 0.60
```

#### Bandwidth Cost (`C_bw`)
> 2KB payload per message. Rate: $0.12 per GB

```
C_bw = ((T_msg × 2) / 1,048,576) × 0.12
```

#### Totals

| Metric | Formula |
|--------|---------|
| **Total Cost** | `C_comp + C_db + C_llm + C_bw` |
| **Unit Cost** | `Total / U` |

---

### 5. Architectural Constraints

- **Tech Stack:** Vanilla HTML/JS, Tailwind CSS (via CDN). No heavy frameworks.
- **Hosting:** Google Firebase Hosting (Single Page Application).
- **Reactivity:** Real-time `oninput` event-driven recalculation.

## Phase 2: Agent Orchestration Artifacts (SDD Workflow)

> The following artifacts were generated by an AI Agent orchestrator based strictly on the SSOT above, prior to any code generation.

---

### Artifact 1: Implementation Plan

1. **Environment Setup:** Create a static `index.html` file and import Tailwind CSS via CDN.
2. **UI Construction:** Build a two-column responsive grid layout. Left column for Input fields (Users, Messages). Right column for the Cost Breakdown dashboard.
3. **State Management:** Attach `oninput` JavaScript event listeners to the input fields to trigger recalculations dynamically without page reloads or submit buttons.
4. **Math Engine Implementation:** Translate the SSOT mathematical formulas into precise JavaScript constants and equations.
5. **Data Binding:** Map the calculated results to the DOM elements, formatting them as USD currency (`$0.00`).
6. **Edge Case Handling:** Add logic `Math.max(0, val)` to prevent negative inputs and handle division by zero for unit costs.

## Phase 4: Pricing Strategy Document

**Document:** AI Chatbot Cloud Architecture Business Strategy  
**Based on:** CFO Bot Unit Economics generated in Phase 3

### Executive Summary

Based on the unit economics mathematically proven by the CFO Bot, we have selected a **Serverless architecture** (Google Firebase + Cloud Functions) coupled with an external LLM API. This strategy provides maximum financial flexibility, scale-to-zero capabilities, and highly predictable operational margins.

### Architectural Justification & Business Strategy

#### 1. Scale-to-Zero Economics

Chatbot traffic is inherently volatile (e.g., high daytime usage, zero nighttime usage). By utilizing **Serverless Compute** (Cloud Functions) and **Serverless Database** (Firestore), our idle cost is strictly **$0.00**. We avoid burning capital on provisioned, always-on servers (like AWS EC2) that drain resources during low-traffic periods.

#### 2. LLM Cost Dominance & Capital Allocation

The CFO Bot reveals a critical insight: **LLM API token costs account for over 95% of the total monthly infrastructure bill** (e.g., $97.50 out of $99.31 in Test Case 2). Therefore, investing engineering hours into complex proprietary cloud orchestration (like Kubernetes clusters) is a misallocation of funds. Our strategy utilizes a lightweight, nearly-free Firebase wrapper, allowing us to focus **100% of our budget directly on LLM intelligence**.

#### 3. Predictable CAC and Profit Margins

The unit economics generated by the bot demonstrate a highly predictable cost per user (e.g., approximately **$0.01 – $0.04 per user** depending on usage). This predictability allows our marketing and finance teams to calculate exact Customer Acquisition Cost (CAC) margins. We can confidently offer a **$5.00/month premium subscription model**, guaranteeing a gross infrastructure margin of **over 90%**, ensuring the business is profitable from day one.
